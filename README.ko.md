# rf-exam-anomaly-poc

[English](README.md) | 한국어

시험장에서 몰래 쓰는 무선 기기(블루투스 이어폰, AI 안경)의 신호를 수신기 스펙트로그램에서 찾을 수 있는지, 합성 데이터로 확인한 개념 검증(PoC) 코드입니다. 기기마다 신호 모양을 미리 알 수 없으므로, 정상 상태를 배우고 벗어난 것을 찾는 이상 탐지를 씁니다.

실험은 두 번 했습니다.

- **두 번째 실험(2026-11-19, 지금 방향):** 장소마다 따로 학습합니다. 그 장소에서 정상 IQ 데이터를 먼저 받고, 그 데이터만으로 가벼운 모델을 학습한 뒤, 같은 장소에서 판정합니다. 장소는 실내 두 곳(같은 방, 다른 날)과 공원입니다. 비교한 방법은 (가) 직전 스냅샷과의 픽셀 차이, (나) 정상 평균과의 픽셀 차이, 크기가 다른 CAE(합성곱 오토인코더) 세 개입니다. 모두 정상 데이터만 씁니다.
- **첫 번째 실험(2026-11-18):** 공원 배경 하나로 학습했습니다. 위 방법에 더해 CNN과 CNN·CAE 앙상블도 비교했습니다.

## 두 번째 실험 결과: 장소별 학습

장소마다 받은 1초 IQ 파일을 시간 순서대로 나눠, 앞 파일로 학습하고 뒤 파일로 시험했습니다. 그 위에 약한 와이파이·블루투스(정상)와 처음 보는 블루투스 2종(이상)을 합성했습니다. 아래는 테스트셋 결과입니다. threshold(이상 점수가 이 값을 넘으면 이상으로 판정하는 경계)는 장소마다 검증셋 정상 이상 점수의 상위 0.1 % 값입니다. CAE는 시드 3개의 평균입니다.

- FPR: 기기가 없는 정상 스냅샷을 이상으로 잘못 판정한 비율
- recall: 기기 신호가 실제로 보이는 스냅샷 중 이상으로 판정한 비율
- SNR: 같은 픽셀 안에서 신호 세기가 배경 잡음 세기보다 몇 dB 센지. 신호가 있는 픽셀은 배경보다 SNR 0 dB에서 3.0 dB, 12 dB에서 12.3 dB 밝습니다. 정상 와이파이·블루투스는 SNR 2–10 dB로 합성했습니다.
- 경보 규칙: 1초에 한 장씩 판정하다가, 최근 10초(10장) 중 2장 이상이 이상이면 경보를 울립니다.
- 시간당 오경보 수: 기기가 없는 정상 상태에서 경보가 1시간에 몇 번 울리는지 센 값
- 이벤트 recall: 기기를 10초 켠 상황 40번 가운데 경보가 울린 비율

| (나) 정상 평균과의 픽셀 차이 | 0.14 | 0.10 | 0.11 | 0.2 | 0.0 | 0.2 |
| CAE, 파라미터 65,265개 | 1.28 | 0.02 | 0.05 | 4.5 | 0.0 | 0.0 |

- 장소마다 따로 학습해야 합니다. 조용한 공원에서 학습한 CAE를 실내에 쓰면 FPR이 2.65–16.90 %로 올랐습니다.
- 같은 장소에서 학습한 CAE의 FPR은 공원과 실내(드론 끔)에서 0.02–0.08 %였습니다. 실내에서는 1.06–1.28 %였는데, 오탐의 62–74 %가 테스트 IQ 파일의 한 장면(2,451 MHz에 짧은 실제 신호가 세 번 되풀이된 곳)에서 나왔습니다. 장소당 배경이 3–5초뿐이라 오탐률이 장면 몇 개에 크게 흔들립니다.
- CAE(파라미터 65,265개)가 recall이 가장 높았습니다. 1/3, 1/10 크기 모델은 SNR 6–9 dB에서 recall이 떨어졌고, SNR 12 dB에서는 차이가 12 %p 이하였습니다.
- 세 CAE 모두 가볍습니다. 1초에 한 장을 판정하면 가장 큰 모델도 CPU 코어 1개 시간의 1 % 미만을 씁니다.
- 모두 합성 이상 신호로 낸 결과입니다. 실제 시험장과 실제 기기로는 확인하지 않았습니다.

## 첫 번째 실험 결과: 공원 배경 하나

공원 배경 3초로 학습하고 시험했습니다. threshold는 검증셋 정상 이상 점수의 상위 0.1 % 값이고, CNN, CAE, 앙상블은 시드 3개의 평균입니다.

**스냅샷 한 장으로 판단할 때 FPR과 recall (%)**

| 방법 | FPR | recall, SNR 0–3 dB | recall, SNR 6 dB | recall, SNR 9 dB | recall, SNR 12 dB |
|---|---:|---:|---:|---:|---:|
| (가) 직전 스냅샷과의 픽셀 차이 | 0.09 | 0.0–0.6 | 0.0–0.3 | 0.5–37.1 | 46.1–88.8 |
| (나) 정상 평균과의 픽셀 차이 | 0.11 | 0.0–0.6 | 0.0–0.3 | 2.7–56.5 | 70.9–92.6 |
| (다) CNN | 0.30 | 89.4–95.5 | 90.7–92.8 | 93.5–95.2 | 94.6–96.7 |
| (라) CAE | 0.05 | 0.0–2.2 | 18.4–41.2 | 73.9–76.8 | 85.4–91.9 |
| (마) CNN·CAE 앙상블 | 0.28 | 88.9–95.3 | 89.9–93.6 | 93.8–96.0 | 94.4–97.4 |

recall의 범위는 이상 신호 2종(이어폰형, BLE형)의 값 중 낮은 값과 높은 값입니다. CNN은 정상 스냅샷과 사각형 덩어리를 합성한 스냅샷을 구분하도록 학습했고, 그 사각형의 크기 범위가 테스트 신호의 크기를 포함해 CAE보다 유리한 조건이었습니다. 앙상블은 CNN과 거의 같았습니다(recall 차이 1 %p 안쪽). 두 번째 실험에서는 정상 데이터만 쓰는 방법으로 범위를 좁혀 CNN과 앙상블을 뺐습니다.

## 저장소 구성

```
rf-exam-anomaly-poc/
├── data/
│   ├── background/      배경 IQ 파일: 공원 Park02_1–3.npy(이 저장소 릴리스), 실내 두 장소 indoor/, indoor_droneoff/(site_setup.py가 만듦)
│   └── raw/hackrf/      실내 원본 IQ 데이터(rf-drone-detector 릴리스의 hackrf_3_test_indoor.tar를 풀면 생김)
├── doc/                 문서 네 개, 그림(fig/ 첫 번째 실험, fig/site/ 두 번째 실험), 선행 조사
├── models/              첫 번째 실험의 학습된 모델(CNN 3개, CAE 3개, 정상 통계, threshold, 앙상블 눈금)
│   └── site/            두 번째 실험의 장소 폴더 3개(장소마다 CAE 9개, 정상 통계, 배경 잡음 세기, 판정 임계값)
├── results/             첫 번째 실험의 기준 결과, results/site/ 두 번째 실험의 기준 결과(재현할 때 비교용)
├── sites/               새 장소에서 학습한 장소 폴더를 두는 곳(site_train.py 출력, 저장소에는 올리지 않음)
├── src/                 학습·평가 코드, 추론 파이프라인
├── requirements.txt
└── LICENSE
```

src/ 안의 파일은 첫 번째 실험 문서 3.5절과 두 번째 실험 문서 3.6절에 하나씩 적었습니다.

## 설치

Python 3.11에서 확인했습니다. PyTorch는 쓰는 컴퓨터에 맞는 버전을 [pytorch.org](https://pytorch.org)의 안내대로 먼저 설치하고, 나머지를 설치합니다.

```
git clone https://github.com/sinkei9456/rf-exam-anomaly-poc.git
cd rf-exam-anomaly-poc
pip install -r requirements.txt
```

학습에는 NVIDIA GPU가 있어야 합니다. 추론은 GPU가 없으면 CPU로 돕니다. 그림 안 글자가 한국어라서 나눔고딕 같은 한글 글꼴이 있으면 좋습니다(없으면 글자만 깨지고 결과는 같습니다).

## 데이터 받기

배경 IQ 파일은 GitHub 파일 크기 한도 때문에 릴리스에 있습니다. 모두 D4D 해커톤 때 HackRF One(20 MS/s, 이득 LNA 16 dB·VGA 16 dB)으로 드론과 조종기를 끄고 받은 데이터이며, CC BY 4.0입니다. 저장소 맨 위에서 내려받아 풉니다.

**공원(두 실험 모두 사용):** 이 저장소 릴리스의 파일 3개(합계 480 MB)입니다.

```
curl -LO https://github.com/sinkei9456/rf-exam-anomaly-poc/releases/download/v1.0/background_park02.tar
tar xf background_park02.tar        # data/background/Park02_1.npy, Park02_2.npy, Park02_3.npy
cd data/background && sha256sum -c SHA256SUMS.txt && cd ../..
```

파일마다 1초 분량(complex64)이고, 1번은 학습셋, 2번은 검증셋, 3번은 테스트셋에 씁니다. 원본은 [rf-drone-detector](https://github.com/sinkei9456/rf-drone-detector) 릴리스 파일 hackrf_1_train_background.tar의 공원 세션 3초이고, 블루투스 모양 덩어리를 지운 뒤 1초씩 나눴습니다(같은 저장소의 src/neo2_pieces.py가 만듦).

**실내 두 장소(두 번째 실험):** rf-drone-detector v1.0 릴리스의 hackrf_3_test_indoor.tar(600 MB)를 받아 풀고, 1초짜리 .cs8 파일을 배경 파일로 바꿉니다.

```

## 사용법 1: 새 장소에 쓰기(학습 → 판정 임계값 → 추론)

시험 장소에서 기기가 없는 정상 상태의 IQ 데이터를 먼저 받아 그 장소 모델을 학습하고, 시험 중 받은 IQ 데이터를 그 모델로 판정합니다. 명령 두 줄입니다.

```
python src/site_train.py --out sites/study_cafe --normal normal_capture.cs8     # 학습, 커널·판정 임계값 선택, 장소 폴더 저장
python src/predict.py --site sites/study_cafe --iq exam_capture.cs8             # 학습 때와 같은 전처리로 판정·경보
```

site_train.py가 차례로 하는 일은 다음과 같습니다. 두 번째 실험과 같은 규칙이고, 합성 정상 신호는 넣지 않습니다(실제 장소 데이터에 그 장소의 정상 신호가 이미 들어 있으므로).

1. 정상 데이터를 시간 순서대로 나눕니다. 앞 75 %는 학습셋, 뒤 25 %는 검증셋입니다.
2. 학습셋으로 배경 잡음 세기를 재고, 모든 데이터를 그 값으로 나눠 스냅샷(256 × 97)으로 바꿉니다.
3. (나) 정상 평균과의 픽셀 차이의 통계와 커널을 정합니다.
4. CAE를 학습합니다. 에포크는 검증셋 정상 재구성 오차로, 커널은 검증셋에 넣은 모양 없는 사각형 패턴으로 고릅니다.
5. 판정 임계값으로 검증셋 정상 이상 점수의 상위 0.1 % 값과 상위 1 % 값을 저장합니다.

장소 폴더에는 site.json(배경 잡음 세기, 커널, 판정 임계값, 학습 기록), pixel_stats.npz, cae<크기>_s<시드>.pt가 생깁니다. predict.py --site는 새 IQ 데이터를 이 폴더의 배경 잡음 세기로 나누므로, 수신기와 수신 설정(중심 주파수, 20 MS/s, 이득)을 학습 때와 같게 둬야 합니다.

| site_train.py 옵션 | 기본값 | 내용 |
|---|---|---|
| `--normal 파일 …` | (필수) | 그 장소의 정상 IQ 데이터. 받은 순서대로 줍니다. 형식은 predict.py와 같습니다(.npy, .cf32, .cs8, .sigmf-data) |
| `--out 폴더` | (필수) | 장소 폴더 |
| `--layout` | chunks | chunks는 20 ms 조각을 이어 붙인 파일(predict.py 입력과 같은 형식), continuous는 끊김 없이 받은 파일(20 ms를 무작위로 자름) |
| `--sizes` | 65k | CAE 크기(65k, 21k, 6k 중 여러 개 가능). 파라미터는 65,265개, 21,121개, 6,489개 |
| `--seeds` | 0 | CAE 시드(여러 개 가능) |
| `--epochs` | 20 | 학습 에포크 |
| `--val-frac` | 0.25 | 검증셋으로 쓸 뒷부분의 비율 |
| `--n-train`, `--n-val` | 10000, 5000 | continuous일 때 자르는 스냅샷 수. chunks일 때 --n-train은 에포크당 학습량 |

| predict.py --site 옵션 | 기본값 | 내용 |
|---|---|---|
| `--model` | cae | cae 또는 pixel((나) 정상 평균과의 픽셀 차이) |
| `--cae` | site.json의 default_cae | 쓸 CAE, 예: 65k_s0, 21k_s0 |
| `--fpr` | 0.001 | 0.001이면 검증셋 정상 이상 점수의 상위 0.1 % 값, 0.01이면 상위 1 % 값을 판정 임계값으로 씀 |
| `--k`, `--n` | 2, 10 | 최근 n장 중 k장 이상이 이상이면 경보 |
| `--noise-ref 파일` | 없음 | 주면 장소 폴더의 배경 잡음 세기 대신 이 정상 데이터로 다시 잼 |

**정상 데이터는 약 30분(최소 10분) 받습니다.** 20 ms 조각을 0.1초마다 받으면 30분에 약 18,000장(HackRF .cs8 파일로 약 14 GB), 10분에 6,000장(약 4.8 GB)이 됩니다. 1초에 한 번만 받으면 판정 임계값을 정할 검증 스냅샷(뒤 25 %)이 모자라므로, 1초에 여러 번 받습니다. 검증 스냅샷이 1,000장보다 적으면 site_train.py가 경고합니다.

**실제 IQ 데이터로 끝까지 시험한 결과:** 실내(10-07) 1초 파일 1–4로 학습하고, 학습에 쓰지 않은 파일 5로 추론했습니다. 학습은 CAE 세 크기를 합쳐 217초 걸렸습니다(NVIDIA DGX Spark, 스냅샷 만들기 44초 포함).

```
H=data/raw/hackrf/1_nodrone_indoor/20261007_antenna_on/recordings
python src/site_train.py --layout continuous --out sites/indoor --sizes 65k 21k 6k --normal $H/0[1-4]/*.cs8
python src/make_site_demo_iq.py --background $H/05/*.cs8 --out data/site_demo_iq.npy --kind 1 --snr 9
python src/predict.py --site sites/indoor --iq data/site_demo_iq.npy
```

| 시험 | CAE, 파라미터 65,265개 | (나) 정상 평균과의 픽셀 차이 |
|---|---|---|
| 파일 5 그대로(정상 20 ms 조각 50개) | 이상 판정 3개, 경보 1번 | 이상 판정 2개, 경보 1번 |
| 파일 5에서 1분(60조각)을 만들고 20–29번에 이어폰형 이상 신호(SNR 9 dB)를 넣음 | 이상 구간 경보 21–37초, 정상 구간 오경보 1번(45–50초) | 이상 구간 경보 21–37초, 정상 구간 오경보 2번(9–18초, 46–52초) |

경보는 이상 판정이 끝난 뒤 10장이 지날 때까지 이어지므로 37초에 꺼집니다. 정상 구간의 오경보는 학습 데이터가 3초뿐이어서 생긴 것으로, 두 번째 실험의 실내 결과와 같은 한계입니다. 두 번째 실험의 모델은 models/site/에 같은 장소 폴더 형식으로 있습니다(`python src/predict.py --site models/site/indoor --iq …`). 공원 폴더의 배경 잡음 세기는 이 저장소 릴리스의 Park02_*.npy 단위라서, 다른 공원 IQ 파일에는 `--noise-ref`를 같이 줍니다.

```

장소 3곳에 대해 아래 단계를 차례로 하고, 끝에 장소 바꿔 쓰기와 결과 표 만들기를 합니다. GPU 1개에서 모두 약 35분 걸립니다.

|---|---|---|---:|

| 2 | src/pixeldiff.py | (가)(나)의 평활 크기와 threshold를 검증셋으로 정하고 점수 계산 | 약 20초 |

| 5 | src/site_cross.py | 다른 장소에서 학습한 모델의 FPR(세 장소가 끝난 뒤 한 번) | 약 2분 30초 |
| 6 | src/site_summary.py | 결과 표(runs/site/results.md)와 요약 그림 | 몇 초 |

- 이미 끝난 단계(데이터 파일, scores_pixel.npz, cae<크기>_s2.pt가 있는 단계)는 건너뜁니다.
- 결과는 runs/site/results.md에 생깁니다. 기준 결과 results/site/results.md와 비교합니다.

## 사용법 4: 첫 번째 실험 모델로 추론

--site 없이 src/predict.py를 쓰면 models/의 첫 번째 실험(공원 배경) 모델로 추론합니다. 새 장소에는 사용법 1처럼 그 장소 데이터로 학습한 장소 폴더를 씁니다. 학습된 모델과 코드만 따로 받으려면 릴리스 파일을 받아 풉니다. 첫 번째 실험은 v1.0의 rf-exam-anomaly-inference-v1.0.zip(2.6 MB), 두 번째 실험과 새 장소 학습은 v2.0의 rf-exam-anomaly-site-v2.0.zip입니다.

먼저 시험용 IQ 파일로 돌려 봅니다. 1분짜리 IQ 데이터에서 20–29초에만 이어폰형 이상 신호(SNR 6 dB)가 들어 있습니다.

```
python src/make_demo_iq.py
python src/predict.py --iq data/demo_iq.npy --noise-ref data/demo_noise_ref.npy --model cnn
python src/predict.py --iq data/demo_iq.npy --noise-ref data/demo_noise_ref.npy --model ens
```

화면에는 다음과 같이 나옵니다.

```
(다) CNN 시드 0, 판정 임계값 2.8855(검증셋 정상 이상 점수의 상위 0.1 % 값), 스냅샷 60장 중 이상 판정 6장
경보(최근 10장 중 2장 이상): 1번
  22–36초(스냅샷 22–36)
결과 파일: runs/predict.csv
```

경보는 최근 10장 중 2장 이상이 이상일 때 켜지고, 마지막 이상 판정 뒤 10장이 지나면 꺼집니다. 그래서 36초까지 이어집니다.

| 입력 옵션 | 내용 |
|---|---|
| `--iq 파일` | IQ 데이터. 1초에 한 번 받은 20 ms 조각(20 MS/s, 400,000 표본)을 시간 순서대로 이어 붙인 파일입니다. 형식은 .npy(복소수), .cf32(complex64), .cs8 또는 .sigmf-data(HackRF int8)입니다. |
| `--snapshots 파일` | 이미 만든 스냅샷(uint8, 장수 × 256 × 97). src/make_data.py가 만드는 형식과 같습니다. |
| `--eval-sets` | src/make_data.py로 만든 검증셋·테스트셋의 점수를 계산해 runs/에 저장합니다. 학습 파이프라인의 --use-released-models가 씁니다. |

| 옵션 | 기본값 | 내용 |
|---|---|---|
| `--model` | cnn | cnn은 (다) CNN, cae는 (라) CAE, ens는 (마) CNN·CAE 앙상블, pixel은 (나) 정상 평균과의 픽셀 차이 |
| `--seed` | 0 | CNN·CAE·앙상블의 시드(0, 1, 2). 앙상블 시드 k는 CNN 시드 k와 CAE 시드 k를 합친 것 |
| `--fpr` | 0.001 | 쓸 threshold. 0.001이면 검증셋 정상 이상 점수의 상위 0.1 % 값, 0.01이면 상위 1 % 값입니다 |
| `--noise-ref 파일` | 없음 | 잡음 세기를 맞출 기준 IQ 데이터. 같은 장소·같은 수신 설정에서 받은 정상 데이터를 권합니다 |
| `--k`, `--n` | 2, 10 | 최근 n장 중 k장 이상이 이상이면 경보 |
| `--interval` | 1.0 | 스냅샷 사이 간격(초). 결과 파일의 시각 칸에만 씁니다 |
| `--out` | runs/predict.csv | 결과 파일 |

결과 파일(CSV)의 칸은 index(스냅샷 번호), time_s(시각, 초), score(이상 점수), threshold, anomaly(이상 판정, 0 또는 1), alarm(경보, 0 또는 1)입니다.

직접 받은 IQ 데이터에 쓸 때는 수신 설정을 학습과 같게 둡니다(HackRF, 중심 주파수 2,449.5 MHz, 20 MS/s, 이득 고정). `--noise-ref`로 정상 상태의 IQ 데이터를 주면 그 평균 전력으로 잡음 세기를 맞춥니다. 두 번째 실험에서 보았듯이 장소가 바뀌면 FPR이 크게 달라지므로, 새 장소에서는 사용법 1처럼 그 장소의 정상 데이터로 다시 학습합니다.

## 재현 확인

**첫 번째 실험:** 이 저장소를 새로 받은 상태에서 두 경로를 돌려 기준 결과(results/)와 비교했습니다. 장비는 NVIDIA DGX Spark(GB10, ARM CPU), Python 3.11, PyTorch 2.14(CUDA 13)입니다.

- 학습된 모델로 재현(`--use-released-models`): 11개 모델(앙상블 3개 포함) × 52개 지표가 모두 같았습니다. 합성 데이터와 픽셀 차이 결과도 같았습니다.
- 처음부터 다시 학습(`bash src/run_all.sh`): 픽셀 차이 결과는 같았고, CNN·CAE·앙상블은 같은 장비에서도 숫자가 조금 달라졌습니다. 시드 하나씩 보면 지표 하나가 최대 9.3 %p(CNN 시드 0) 달랐습니다.
- 문서에 쓰는 시드 3개 평균으로 보면 차이가 작습니다(아래 표). 결론은 같습니다.

처음부터 다시 학습했을 때 기준 결과와의 차이 (시드 3개 평균, threshold는 검증셋 정상 이상 점수의 상위 0.1 % 값)

| 모델 | 스냅샷 recall 차이 중 가장 큰 값 (%p) | 이벤트 recall 차이 중 가장 큰 값 (%p) | 테스트셋 FPR, 기준 결과 (%) | 테스트셋 FPR, 다시 학습 (%) | 1시간 경보 수, 기준 결과 (회) | 1시간 경보 수, 다시 학습 (회) |
|---|---:|---:|---:|---:|---:|---:|
| (다) CNN | 2.7 | 0.0 | 0.30 | 0.27 | 0.5 | 0.4 |
| (라) CAE | 0.5 | 1.7 | 0.05 | 0.05 | 0.0 | 0.0 |

**두 번째 실험:** results/site/의 결과는 2026-11-19에 같은 장비에서 한 번 돌린 결과입니다. 이 저장소를 새로 받아 실내 데이터를 내려받고 site_setup.py로 만든 배경 파일 10개는 연구에 쓴 파일과 모두 같았습니다. PyTorch는 GPU 학습을 시드만으로 똑같이 되풀이한다고 보장하지 않으므로, CAE 숫자는 다시 돌리면 조금 달라질 수 있습니다.

## 한계

- 장소마다 배경 IQ 데이터가 3–5초뿐입니다. 실제 운용에서는 장소마다 수 분 이상 정상 데이터를 받아야 합니다.
- 정상 블루투스를 모두 짧은 패킷(0.4 ms 이하)으로 합성했습니다.
- 이상 신호 2종은 블루투스 규격 숫자로 만든 흉내이고, 실제 기기 신호가 아닙니다. AI 안경과 핸드폰 사이 통신은 와이파이를 함께 쓸 수 있으나 확인하지 않았습니다.
- 실내 두 장소는 같은 방이지만 날짜와 수신 설정(중심 주파수, 필터, 수집 프로그램)이 다릅니다.
- 좌석 위치 추정, 사람 몸에 의한 신호 약화는 다루지 않았습니다.
